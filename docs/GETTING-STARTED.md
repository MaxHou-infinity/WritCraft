# 从安装到第一篇作品

这份指南面向第一次使用笔触 · WritCraft 的作者。整个过程约需 10 分钟。

> 当前版本是 macOS Developer Preview。正式写作前，请先备份项目；不要用唯一副本直接测试。

## 1. 安装运行环境

笔触当前需要：

- macOS 12 或更高版本，Apple Silicon 与 Intel Mac 均可；
- Node.js 22.12 或更高版本；
- npm 10 或 npm 11。

在“终端”中检查：

```bash
node --version
npm --version
```

如果没有 Node.js，建议从 [Node.js 官网](https://nodejs.org/) 安装当前 LTS 版本。安装完成后重新打开终端。

## 2. 检查并启动

先做一次零网络环境检查：

```bash
npx writ-craft@preview --check
```

检查通过后启动：

```bash
npx writ-craft@preview
```

首次启动可能需要下载 Electron 运行时，因此会比之后稍慢。请保持网络连接，不要连续重复执行命令。

如果希望把本次体验与既有配置完全隔离：

```bash
mkdir -m 700 "$HOME/WritCraft-Preview-Profile"
npx writ-craft@preview --profile "$HOME/WritCraft-Preview-Profile"
```

## 3. 准备第一个项目

笔触把一个普通文件夹视为一个写作项目。推荐结构：

```text
我的写作项目/
├── edit.md
├── chapters/
│   ├── 01-开篇.md
│   ├── 02-问题.md
│   └── 03-方法.md
└── references/
```

`edit.md` 是项目级写作说明。至少写清楚：

```markdown
# 项目意图

## 主旨
这部作品最想讲清楚什么？

## 目标读者
谁会阅读？他们已经知道什么？

## 写作目标
读完后，希望读者理解、相信或采取什么行动？

## 结构
- 第一部分：
- 第二部分：
- 第三部分：

## 边界
哪些观点、语气或事实不能被 AI 擅自改变？
```

已有 Markdown 项目也可以直接打开。体验前请复制一份，不要拿唯一原稿测试 Preview。

## 4. 配置 MiniMax

1. 打开笔触的设置；
2. 找到 MiniMax API Key；
3. 将 Key 粘贴到设置界面并保存；
4. 回到项目后再发起 AI 操作。

不要把 Key 写进 `edit.md`、`.env`、终端参数、GitHub Issue 或截图。`sk-cp-` 与 `sk-api-` 都可以配置，但文本、图片模型是否可用以及费用多少，由你的 MiniMax 套餐、Credits 和实时额度决定。

## 5. 推荐的第一次工作流

1. 打开 `edit.md`，确认主旨、读者和结构；
2. 用项目对话让 AI 复述它对作品的理解；
3. 打开一个章节，选中一段文字后按 `⌘K`，输入本次改写要求并按 Enter 生成预览；用 Tab 接受、Esc 拒绝，或在预览中重载；
4. 不知道下一步时打开“写作导航”，选择一条建议并点击“处理这个建议”；正文内会直接显示红删绿增 Diff，确认前不会写入文件；
5. 只有需要自行发起独立跨文件修改时才进入 Changes；普通导航建议不要求在 Research 与 Changes 之间来回切换；
6. 打开一致性图谱，检查概念、人物、变量和时间关系；
7. 重启笔触，确认项目和历史状态能够恢复。

当前公开的 `0.1.2` Preview 已包含“处理这个建议 → 正文内 Diff → 接受、拒绝或安全撤销”的统一任务流；项目首页、当前文稿大纲、`⌘P` 快速打开和可恢复导航属于 `0.2.0` 候选能力。旧 Plan 任务图已经退役，请不要按旧说明操作。

左侧活动栏用于切换项目文件、全文搜索、来源与证据和一致性星图；选中的图标会有明确高亮。星图会占据完整工作区，返回文件时点击“项目文件”或“返回写作”。需要新建或打开其他项目时，点击项目名称右侧的 `•••`；这两个低频入口不会常驻占用侧栏。

## 6. 常见问题

### `npx` 提示 npm 版本不支持

当前 Preview 支持 npm 10 和 npm 11，不支持 npm 12。执行 `npm --version` 确认版本。

### 第一次启动很慢

首次启动可能从 Electron 官方发布源下载运行时。等待当前命令完成，不要同时启动多个实例。

### AI 没有响应

依次检查网络、Key 是否保存、MiniMax 套餐额度，以及应用中的错误提示。不要在公开 Issue 中粘贴 Key、完整 Prompt、文稿或服务商原始响应。

### 修改只出现在审阅区，没有写入文件

这是差异审阅流程的一部分。只有明确接受修改后，笔触才会尝试写入。若接受后仍未落盘，请先停止重复点击，导出隐私诊断并提交 Issue。

### 如何安全报告问题

优先使用应用内“诊断导出”，确认预览中没有正文、路径或凭证后再保存。普通 Bug 可提交 GitHub Issue；安全或隐私问题请遵循 [`SECURITY.md`](../SECURITY.md)。

## 7. 卸载与数据

笔触不会把你的 Markdown 项目封装成专有文件。停止使用不会删除项目内容。

如需清理 `npx` 下载缓存，可按 npm 官方方式管理缓存；不要在不理解影响时删除整个用户目录。使用 `--profile` 创建的隔离目录可在确认不再需要后由你手动删除。
