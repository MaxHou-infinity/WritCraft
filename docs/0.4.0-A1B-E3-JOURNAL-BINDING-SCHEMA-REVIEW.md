## 1. 窄层签收边界

本记录只绑定：

- `writcraft.public-markdown-existing-journal-binding/v1` 的 descriptor-exact ordered keys、完整 WRCCHRJ2 journal file identity、root/recovery identity digests、slot/head/predecessor 与双 marker digest；
- generation parity（偶数 `A`、奇数 `B`）、canonical unsigned decimal、whole-file size ≥ frame、VALUE payload 完整覆盖 frame、active-marker slice 位于 payload 且不含 frame 尾部 LF；
- REQUEST 的 `journalMarkerBinding` sibling，以及 E/R header 的完整 23-field ASCII order（含 operationId、requestDigest、bindingDigest 与 bounded physical slices）；
- 独立 1-item golden、hostile descriptor/extra/accessor/symbol/prototype、identity/content/range/digest drift、zero/non-zero generation predecessor、max accepted/+1 budget 证据。

本记录不签 C helper、Main/IPC/preload/Renderer、post-E journal CAS、fresh R/V、F/ACK、`ROLLBACK_CREATE`、multi-item mutation、mixed transaction、A1b 总体、A1c、A2、Stage A 或 0.4.0 candidate/release。

## 2. 首红与修订事实

1. 首红为独立 binding test 的缺失模块/API：production schema 尚未提供 `EXISTING_JOURNAL_BINDING`。
2. 首轮 reviewer finding 为 P0=0、P1=2、P2=0：binding budget 未复用 permanent-journal 的 exact `MAX_VALUE_BYTES`/`MAX_ACTIVE_MARKER_BYTES`/`MAX_HEADER_BYTES` 语义；E/R header 缺少 frozen `operationId` 字段。
3. 修订复用 `changes-history-marker-journal-schema.js` 的 limits，要求 `payloadOffset + payloadByteLength === frameByteLength`、marker 完全在 payload 且不覆盖末尾 LF、frame 不超过 full journal identity size；E/R header 改为 `command, operationId, requestDigest, bindingDigest, ...` 的 23-field order。
4. 修订测试补齐 hardcoded binding digest、exact key arrays、slot/generation parity、generation 0/null predecessor、non-zero predecessor、full identity mode/nlink/size/content drift、all logical/canonical digest tamper、head decimal/journalId/value hostile、frame/payload/marker/max/+1、accessor/hidden/Symbol/prototype rejection。
5. 同一 reviewer 对修订 payload 复核 P0=0、P1=0、P2=0；该结论不是本记录的 final binding 自签。
