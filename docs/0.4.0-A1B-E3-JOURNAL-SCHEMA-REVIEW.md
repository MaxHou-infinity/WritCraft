## 1. 签收边界

本记录只绑定以下纯 authority：

- permanent journal VALUE 新增 nullable sibling `existingTerminalPublication`，不覆盖 CREATE `nativePublication`；
- 1..299 item、768 KiB publication envelope、descriptor-exact final leaf/control/apply identities；
- post-E Main-owned install CAS 对 immediately preceding VALUE digest 与 next generation 的绑定；
- `COMMITTED → FINALIZED → ACK_COMMITTED`，以及 EXISTING authority 在 ACTIVE 中不得被提前丢弃；
- terminal cleanup 分别绑定 CREATE 与 EXISTING 状态/self digest，再用有序 publication-set digest 收口；
- ACTIVE→IDLE 同时验证并清除两条 publication；
- existing legacy marker integrity 保持 insertion-order-sensitive `SHA256(JSON.stringify(validated payload))`，journal/native canonical digest 保持不变。

本记录不签 Main post-E publication CAS、native fresh `R`、`V`、`F`、multi-item mutation、`ROLLBACK_CREATE`、mixed transaction、A1b 总体、A1c、A2、Stage A 或候选/发布。

## 2. 首红、P1 与修订事实

1. production schema 首红为 VALUE exact key set 拒绝 `existingTerminalPublication`。
2. 新 exact sibling 导致旧 physical/service fixture 少显式 null，在进入业务逻辑前被拒；生产 initial/ACTIVE/IDLE 构造器与 fixture 同步显式 null，没有增加缺省兼容后门。
3. 首轮独立复核中 pure schema 静态项与 26/26 已绿，但 registered reconciliation-read 在 legacy marker integrity 处首红，finding 为 P0=0、P1=1、P2=0。
4. 根因为 reconciliation service 的通用 `canonical()` 曾被切换到 canonical JSON，连带改变了合同冻结的 legacy marker insertion-order digest；不得以改 fixture 或改合同掩盖。
5. 修订加入唯一内部 `sealValidatedMarker`：先以完整业务 validator 归一 payload，再对归一后的固定键序 `JSON.stringify` 求 legacy digest，再执行普通完整验证。`skipIntegrity` 只存在于该未导出的 provisional 内部调用。
6. `validateArtifactBinding` 显式按固定键序重建嵌套 identity，防止 journal canonical JSON roundtrip 改变 legacy integrity。所有七个 marker producer 均统一走 seal，journal/native truth 继续使用 canonical digest。
7. 同一 reviewer 对新五文件 hash 定点复核为 P0=0、P1=0、P2=0；该内容结论不是本记录的 final binding 自签。
