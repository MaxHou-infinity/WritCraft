# 0.4.0 A1b EXISTING / ROLLBACK_CREATE State Matrix

> Freeze: 2026-08-13
> Scope: Stage A / A1b only. This file is an execution matrix, not a
> production sign-off. It does not authorize A1c, A2, Main IPC, Renderer, or
> a second recovery authority.

## 1. Contract authority and current conclusion

The governing contract is section 4.2 of
`docs/CHANGES-HISTORY-RECOVERY-V1-CONTRACT.md`, together with section 4.3 for
`ROLLBACK_CREATE`, `v0/src/main/snapshot-existing-restore-native-schema.js`,
`v0/native/public-markdown-create-helper.c`, and the registered focused tests.

The required mixed path is:

```text
PRECREATE
  -> CREATED_RECEIPT
  -> EXISTING_COMMITTED       (E/R = COMMITTED, then V exact)
  -> HISTORY_COMMITTED
  -> FINALIZED                 (F, then marker clear/ACK)
```

The only legal zero-net-write mixed branch is:

```text
CREATED_RECEIPT
  -> CREATE_ROLLBACK_QUARANTINED
  -> ROLLED_BACK               (E/R = UNCOMMITTED, exact base History)
```

`UNKNOWN` is not a phase and cannot be persisted as progress. It locks the
previous exact phase for fresh reconciliation. The current native E transport
consumes an E header/items and performs partial held-fd preflight, but returns
only `UNKNOWN`; R/V/F have no production existing dispatcher. Therefore A1b is
not signed.

Across a restart, authority must be rebuilt from the persistent preimage in the
exact marker, immutable artifact, original selection/phase and raw base-History
binding. A scan of current public files or private record names is never a
replacement for that stored preimage.

## 4. Per-item mutation and failure matrix

The E implementation must treat each item as a three-state external
transaction. The table below is the minimum evidence needed before an aggregate
state can be returned.

| Boundary | Required proof | Failure classification | Cleanup rule |
|---|---|---|---|
| Before first write | Current leaf fd, full identity, content SHA, revision, selected/path/ancestor and base History all match | `UNKNOWN` before mutation | No cleanup; preserve marker/artifact |
| Control create | `O_CREAT|O_EXCL`, owner `0600`, exact canonical control bytes, fd identity, file fsync and recovery-dir fsync | `UNKNOWN` if any proof is incomplete | Never unlink by path; retain foreign/partial control |
| Public replace | Descriptor-relative parent, no-follow traversal, before fd still exact, after bytes read only from artifact range, same-volume `RENAME_SWAP` or equivalent no-clobber atomic replacement with held before/stage fds, and both public-parent/recovery fsyncs | `UNKNOWN` for same-inode rewrite, same-byte new inode, ancestor/root drift, or post-rename uncertainty | Reconcile exact inode/locator identities; never infer commit from visible bytes or adopt an unbound residue |
| After receipt | Reopen public leaf; reproduce after identity under the unique leaf schema; fsync public parent and recovery dir | `UNKNOWN` if identity or durability differs | Preserve control and any receipt; no rollback claim yet |
| Self-rollback | Only if the operation has formally entered rollback and the exact before bytes/identity are still authoritative | `UNKNOWN` if one item fails or current History drifts | A partial rollback cannot be published as UNCOMMITTED |
| Aggregate terminal | All items in parent order; unique final leaf identities; exact receipt-set and terminal self digests | `UNKNOWN` on any omission, reorder, duplicate, cross-operation or mixed state | Keep prior marker phase locked |

## 5. Response-loss and identity-drift rules

### 5.1 E-3 P1 refreeze: durable publication identity

The current control/apply files are not, by themselves, a cross-process
publication anchor: a same-byte replacement can preserve every canonical byte
while changing the inode. E-3 therefore adds one nullable
`existingTerminalPublication` field to the A1a permanent-journal VALUE. It is a
sibling of, never a replacement for, the already occupied CREATE_MISSING
`nativePublication`; no second marker, sidecar or overloaded terminalCleanup is
legal.

The only initial install is a single ACTIVE journal CAS from mixed
`CREATED_RECEIPT` that preserves the CREATE publication, installs a complete
COMMITTED EXISTING publication, and advances the active marker to
`EXISTING_COMMITTED`. The publication is capped at 768 KiB and 1..299 ordered
items. It binds the exact original request/marker/artifact/History/root/recovery
authority, immediately previous VALUE digest and next generation, complete
final-leaf identity, complete control/apply publication identities, receipt-set
and terminal digests, plus its own non-circular digest. The containing VALUE
continues to own current predecessor/generation/self authority.

This is a post-helper Main CAS. Raw E stdout must first parse as a complete
terminal, after which Main reopens every returned identity and appends the
publication. Raw helper response loss before the CAS is `UNKNOWN`/manual and
cannot be reconstructed; E is never replayed. A durable journal CAS followed
by Main/App response loss is reconstructed through DISCOVER/READ and fresh R.
An unknown CAS outcome is settled only from journal truth; absent publication
never authorizes current-inode recapture.

R receives the stored publication and is read-only. It may reproduce COMMITTED
only by descriptor-reopening the stored record/leaf identities and exact
non-public authority; same-byte/new-inode, same-inode rewrite, foreign/missing
record, transient locator or journal drift is `UNKNOWN` and preserved.

The publication remains immutable through `HISTORY_COMMITTED`, then gains one
exact finalization and state `FINALIZED` only from stored F truth. Exact ACK of
the stored final/control/apply identities advances it to `ACK_COMMITTED`. It is
retained until the final ACTIVE→IDLE terminal cleanup binds both the CREATE
publication and this ACK_COMMITTED EXISTING publication; no earlier cleanup or
field clearing is valid.

That cleanup has separate CREATE/native and EXISTING state+digest fields plus
one ordered publication-set digest over `{operationId, kind,
nativePublicationDigest, existingTerminalPublicationDigest}`. Mixed Snapshot
requires both states ACK_COMMITTED; full-missing requires CREATE ACK_COMMITTED
and EXISTING NONE; ordinary compatibility requires both NONE. The final journal
transition verifies the two surviving self digests, atomically clears both
publication fields, and cannot accept a single ambiguous publication digest.

| Event | Required next action | Forbidden shortcut |
|---|---|---|
| Raw E process exits abnormally, stdout is empty/malformed, or response times out before publication CAS | `UNKNOWN`/manual; retain `CREATED_RECEIPT` and every residue | Re-run E; call R without stored publication; trust visible records or recapture current identities |
| EXISTING publication journal CAS response loss | DISCOVER/READ the exact old/new heads; after exact COMMITTED install, fresh R receives the stored publication and V rechecks it | Re-run E; infer install from visible records |
| R response loss | Fresh R-only reconciliation using exact original authority plus the same stored publication | Re-run E or assume UNCOMMITTED from absence |
| V response loss | Fresh V using the same terminal receipt and authority | Mint a new receipt or advance phase |
| F response loss | Fresh `reconcileFinalize` for the stored final record/identity | Repeat F blindly or clear marker from a path lookup |
| Same-byte new inode | `UNKNOWN`; preserve replacement and all recovery records | Treat content equality as identity equality |
| Same-inode rewrite or metadata/timestamp drift | `UNKNOWN`; preserve the fd/path state | Trust old digest or inode alone |
| Ancestor/project/root/recovery replacement | `UNKNOWN`; stop all mutation | Re-open through absolute path or infer project identity from path text |
| Base History raw byte/identity drift | `UNKNOWN`; retain exact prior phase | Parse and accept semantically equivalent JSON |
| Missing record or partial record set | `UNKNOWN` unless the exact stored terminal proves the missing record is a committed cleanup result | Treat absence as COMMITTED/UNCOMMITTED |

## 5.2 WRCCHRJ2 physical bridge refreeze (E-3 stop boundary)

This is a contract-only refreeze after repeated publication-identity P1s. It
does not claim that Main, the native helper, or the lifecycle adapter has been
implemented. The single authority is the existing permanent WRCCHRJ2 journal;
legacy JSON marker bytes are migration evidence only and are never an E request
field, held publication fd, CAS preimage, or fresh-R source. No sidecar, second
marker, second journal, index, scanner, or current-inode recapture is allowed.

The exact bridge schema is
`writcraft.public-markdown-existing-journal-binding/v1`. Its ordered keys are:

```text
schema, journalBasename, journalMagic, journalFileIdentity,
rootIdentityDigest, recoveryDirectoryIdentityDigest, activeSlot, head,
previousValueDigest, frameByteLength, frameSha256, payloadOffset,
payloadByteLength, payloadSha256, activeMarkerOffset,
activeMarkerByteLength, activeMarkerDigest, activeMarkerCanonicalSha256,
bindingDigest
```

`journalBasename == changes-history-transaction.json`, `journalMagic ==
WRCCHRJ2`, `journalFileIdentity` is the complete owner-only `0600`, regular,
one-link `writcraft.object-identity/v1` whose `contentSha256` covers the full
physical journal bytes, and `head` is the exact
`writcraft.changes-history-marker-journal-head/v1` (`schema`, `journalId`,
decimal `generation`, `valueDigest`). `activeSlot` is `A|B`; offsets/lengths
are safe non-negative integers; digest values are lowercase `sha256:` values,
with nullable `previousValueDigest` only at generation zero. Root and recovery
identity digests are mandatory fields of this binding, not inferred from a
path or a legacy marker. `activeMarkerDigest` is the section 3.1.4 logical
digest; `activeMarkerCanonicalSha256` is the raw SHA-256 of the exact canonical
UTF-8 JSON slice, and both are required.

`bindingDigest` uses the repository digest domain over this exact schema with
only `bindingDigest` set to null:

```text
SHA256(UTF8("writcraft-digest/v1") || 0x00 ||
       UTF8("writcraft.public-markdown-existing-journal-binding/v1") || 0x00 ||
       canonicalJson(exact binding with bindingDigest == null))
```

The generic `JOURNAL_MARKER_BINDING` preimage is reserved for CREATE/legacy
compatibility and is not valid for E/R. E/R `REQUEST` adds the exact sibling
`journalMarkerBinding` before `items`; `AUTHORITY` is the complete logical
marker authority + this binding + ordered selection + `CREATED_RECEIPT` phase +
request. A digest-only sibling is invalid.

| Boundary | Required physical authority | Required action / failure rule |
|---|---|---|
| E request before spawn | Complete `journalMarkerBinding` above, plus the complete original E/artifact/History/leaf authority. The only E/R descriptors are `fd3=root`, `fd4=artifact`, `fd5=journal`, `fd6=History-parent`, and `fd7=base-History` when present; absent History uses fd7 as the same fd6 directory authority. There is no `markerFd`. | Main must join all fields to one exact ACTIVE `CREATED_RECEIPT` VALUE with no stored EXISTING publication. Any mismatch, legacy-only marker, marker fd, or missing field is `UNKNOWN`/manual before E or mutation. |
| E post-helper pre-CAS | Reopen the journal descriptor-relatively; reproduce the complete old physical binding and exact active-marker slice/digest; reopen control/apply/public leaf, artifact, root/recovery and raw History identities | A complete COMMITTED E terminal is only a candidate. Any journal/root/recovery/record/leaf/History drift is `UNKNOWN`; do not append or clean up. |
| Main publication CAS | Exact old head → inactive-slot next frame; `generation + 1`, `previousValueDigest == old.valueDigest`, same journal ID, canonical ACTIVE marker update to `EXISTING_COMMITTED`, and complete stored `existingTerminalPublication` | One APPEND only. Native fsyncs frame/file, reopens basename, verifies new slot/frame/head/valueDigest and full journal-file identity. No path-visible records can substitute for this CAS. |
| Post-CAS / cleanup | New WRCCHRJ2 head plus root/recovery identity, exact stored control/apply/public/History/artifact identities, and the required post-commit cleanup state | Main rechecks before phase/result advance. Failure after helper mutation but before complete proof is `UNKNOWN`/manual and preserves journal and residue. |
| APPEND response loss | `DISCOVER` and exact `READ` limited to the old/new expected heads and physical predecessor chain | Exact old head with no publication means CAS not observed; exact new head containing the stored publication means CAS committed; absent/conflicting/ambiguous head is `UNKNOWN`/manual. Never replay E or rebuild from current records. |
| Fresh R | Journal-stored publication and all descriptor-exact identities from that publication; no live recapture | Read-only descriptor reopen. Publication absence, transient before/stage residue, same-byte/new-inode, same-inode rewrite, journal/ancestor/History drift, or response loss is `UNKNOWN` and preserved. |

The E request therefore no longer depends on a legacy JSON marker fd. The
legacy file may be read only by a separately classified migration path and
cannot authorize E, CAS, cleanup, or fresh R. JS serializes the binding in the
exact key order above; C receives the same ordered ASCII-tab header fields:
`command, operationId, requestDigest, bindingDigest, journalBasename, journalMagic,
activeSlot, journalId, generation, previousValueDigest, valueDigest,
frameByteLength, frameSha256, payloadOffset, payloadByteLength, payloadSha256,
activeMarkerOffset, activeMarkerByteLength, activeMarkerDigest,
activeMarkerCanonicalSha256, rootIdentityDigest,
recoveryDirectoryIdentityDigest, itemCount`. `operationId` is the exact
request operation ID used to rebuild operation-bound private names and
digests; the one-way request digest cannot replace it. The binding/header cap is 1,024
bytes, each item line is capped at 2,048 bytes, and the complete E/R request
remains capped at 4 MiB and response at 768 KiB; `+1`, reordered/extra fields,
non-canonical decimals, invalid UTF-8 or trailing bytes fail closed. This
refreeze is a blocker boundary, not an implementation sign-off.

## 6. Independently testable slices

Each slice must have one production first-red, a focused gate, and a hard exit
condition. A green pure-schema test is not a cross-layer sign-off.

### Slice E-1: canonical and authority parity

- Scope: JS canonical control/apply/terminal bundle and native test-mode
  serializers only; no Markdown mutation.
- First red: one real authority encoded through the production E wire has a
  native `K NAME/K CONTROL` byte or digest differing from the JS golden.
- Exit: byte-for-byte control, apply, deterministic names, and terminal digest
  parity; malformed/extra/accessor/drift cases reject before any mutation.

### Slice E-2: one-leaf descriptor-bound execute

- Scope: one EXISTING leaf, exact before proof, after bytes from artifact,
  control/apply receipt and public parent/recovery fsync.
- First red: valid real fixture currently returns `UNKNOWN` where the contract
  requires COMMITTED; the preserved production test is
  `verify-v0-public-markdown-native-lifecycle.js`.
- Exit: exact COMMITTED terminal parses through the JS schema and every
  same-byte/new-inode/same-inode/ancestor/history drift case remains
  `UNKNOWN` with no foreign cleanup.

### Slice E-3: publication CAS plus fresh R/V reconciliation and response loss

- Scope: Main validation of a complete E response, permanent-journal publication
  CAS/response loss, stored-identity R reconstruction and V exact terminal
  verification; no E replay.
- First red: raw E response loss has no safe cross-process publication identity;
  journal-backed Main/App response loss cannot yet reproduce COMMITTED.
- Exit: raw helper response loss remains manual; after a durable publication CAS,
  response-loss evidence proves COMMITTED and UNKNOWN, V returns the same terminal,
  and no path re-runs E or trusts process status.

### Slice E-4: F/reconcileFinalize publication

- Scope: deterministic final record, final identity, F response loss and exact
  ACK/marker-phase consumption; no ROLLBACK_CREATE mutation yet.
- First red: F response loss cannot reproduce the same final record/identity
  through a fresh transport.
- Exit: F and reconcileFinalize are exact and idempotent for one authority;
  moved/duplicate/foreign/final-record replacement remains UNKNOWN.

### Slice R-1: `ROLLBACK_CREATE` after formal UNCOMMITTED

- Scope: separate Q/R/D/A domain, same marker/artifact/base History, receipt-owned
  MISSING leaves only. It begins only after E/R has produced formal UNCOMMITTED.
- First red: a Q/R/D/A wire cannot independently rebuild the original
  PRECREATE/CREATED_RECEIPT and complete formal EXISTING UNCOMMITTED authority.
- Exit: only exact all-created-leaf rollback reaches ROLLED_BACK; partial,
  foreign, response-loss, or History drift remains UNKNOWN. This slice is
  intentionally downstream of E-3/E-4 and cannot be started as a substitute.

## 7. Current implementation evidence and blockers

- Pure schema: `verify-v0-snapshot-existing-restore-native-schema.js` is
  `19/19`; this proves descriptor/canonical contracts only.
- Transaction focused evidence: `verify-v0-snapshot-public-markdown-transaction-phase.js`
  is `86/86`; mixed entry wiring is structural and does not execute E.
- Native lifecycle focused evidence: the registered lifecycle test includes a
  real authority fixture. Its preserved first red is valid E authority,
  actual `UNKNOWN`, expected `COMMITTED`.
- Native strict compile is green for the current helper and test-mode
  canonical helper. The test-mode canonical path currently signs only control
  name/control-record parity; it does not sign apply, terminal, mutation, R/V,
  or F.
- Current C transport consumes the E header/items and preflights selected held
  descriptors, but emits stable UNKNOWN. It has no production E mutation or
  R/V/F dispatcher. Existing rollback helper builders are not an E executor and
  cannot be relabeled as E authority.

The minimum next implementation boundary is E-1 completion followed by E-2.
Until E-3 and E-4 close the response-loss and terminal publication matrix, the
mixed transaction must remain locked at `CREATED_RECEIPT`; until R-1 closes,
`ROLLBACK_CREATE` must remain unavailable. No focused green in this document
authorizes A1b sign-off.
