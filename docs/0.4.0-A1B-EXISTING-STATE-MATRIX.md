## 1. Product boundary

A1b keeps the approved mixed-restore target: one author-confirmed selection may contain both
existing Markdown and snapshot Markdown whose public path is currently missing. The complete
selection is one Changes/History transaction. It must never silently split into two author
operations, delete unselected files, restore images, or infer success from visible bytes.

The mainline is:

```text
PRECREATE -> CREATED_RECEIPT -> EXISTING_COMMITTED
          -> HISTORY_COMMITTED -> FINALIZED -> terminal applied
```

The only zero-net-write branch is:

```text
CREATED_RECEIPT -> CREATE_ROLLBACK_QUARANTINED -> ROLLED_BACK
```

`UNKNOWN` is not a phase. It preserves the prior durable phase and blocks new mutation until
fresh reconciliation or manual recovery establishes truth.

## 2. Shared authority

Every E/R/V/F or rollback entry binds the same operation, project instance, immutable artifact,
ordered parent selection, public-Markdown phase, exact base History, trusted root/recovery
authority and the complete selected item set.

For each EXISTING item, authority includes selected ID, NFC relative path, before/after revisions
and artifact ranges, ancestor identity, exact before-leaf identity and content digest. For each
MISSING item, authority includes the durable CREATE publication and created-leaf identity.

The permanent WRCCHRJ2 journal is the sole restart publication authority. Legacy JSON marker
bytes are migration evidence only; no second marker, sidecar, scanner or current-inode recapture
may authorize A1b.

## 3. Three-state rule

| State | Minimum proof | Allowed next action |
|---|---|---|
| `COMMITTED` | Every selected mutation, formal record, public leaf, History binding and required directory fsync is exact | Persist the exact publication/phase or continue the signed mainline |
| `UNCOMMITTED` | Every selected public leaf and raw History are exactly operation-before; no partial mutation or unowned residue remains | Enter the formal rollback branch or return a proven zero-write result |
| `UNKNOWN` | Either terminal proof is incomplete, conflicting or unavailable | Preserve journal, records and residue; fresh reconcile or manual recovery only |

Absence, process exit, timeout, same bytes, one matching digest or one surviving record never
upgrades `UNKNOWN` to `COMMITTED` or `UNCOMMITTED`.

## 4. EXISTING lifecycle

| Entry | Preconditions | Mutation / proof | Terminal rule |
|---|---|---|---|
| `E execute` | `CREATED_RECEIPT`; complete ordered EXISTING authority; exact base History and all before leaves | Descriptor-bound replace from immutable artifact; durable control/apply records; public and recovery directory fsync | Return candidate `COMMITTED` only for the complete ordered set; partial or drift is `UNKNOWN`; never replay E after an uncertain outcome |
| `R reconcile` | Original authority plus journal-stored EXISTING publication | Read-only reopen of stored record and leaf identities; no identity recapture or cleanup | Reproduce only the stored terminal; missing/foreign/transient state is `UNKNOWN` |
| `V verify` | Exact authority plus E/R terminal | Pure fresh recheck of records, leaves, History, ordering and terminal digest | Return the same terminal or `UNKNOWN`; never advance phase from a mismatch |
| `F finalize` | Verified `COMMITTED`; `HISTORY_COMMITTED`; stored publication exact | Publish/acknowledge one deterministic final record and fsync it | Only exact final publication may advance to `FINALIZED`; uncertain response stays `UNKNOWN` |
| `reconcileFinalize` | Stored final request/publication and fresh transport | Read-only reproduction of the same final identity | Same result or `UNKNOWN`; no blind F replay |

Main treats a complete E result as a candidate until it rechecks the non-public/public authority
and installs `existingTerminalPublication` with one WRCCHRJ2 compare-and-append transition.
Only that stored publication can authorize fresh R/V and later finalization.

## 5. Per-item failure matrix

| Boundary | Required proof | Failure result |
|---|---|---|
| Before first write | root/recovery/artifact/History/ancestor/before leaf all exact | `UNKNOWN`, zero new mutation |
| Control publication | owned exact record, durable file and recovery-directory fsync | `UNKNOWN`; preserve foreign or partial record |
| Public replacement | exact held before authority, artifact bytes, atomic replacement and both directory fsyncs | `UNKNOWN`; do not infer from current content |
| Apply publication | exact final leaf and formal record identities, no unbound transient | `UNKNOWN`; preserve records |
| Aggregate terminal | all items in parent order, unique identities, complete receipt-set and terminal digest | `UNKNOWN` on omission, reorder, duplicate or mixed state |
| History commit | exact prepared History derived from the same full selection | prior phase remains locked |
| Final cleanup | stored CREATE and EXISTING publications both acknowledged | no early deletion or field clearing |

## 6. `ROLLBACK_CREATE`

Rollback is a separate command domain but consumes the same operation, artifact, selection,
History and journal authority. It is legal only after formal EXISTING `UNCOMMITTED` proves every
EXISTING leaf and raw History are exactly operation-before.

| Step | Allowed action | Success condition |
|---|---|---|
| Q | Move only receipt-owned MISSING leaves to private quarantine | every selected created identity is exact and quarantine publication is durable |
| R | Freshly reconcile Q from stored identities | complete same Q truth; partial/foreign state is `UNKNOWN` |
| D | Delete only the exact quarantined identities after rollback authority is durable | every deletion and recovery-directory fsync is proven |
| A | Acknowledge exact rollback records and publication | phase reaches `ROLLED_BACK`; public files and History equal operation-before |

Any existing-file drift, missing receipt, foreign replacement, partial quarantine/deletion,
History drift or response loss without stored proof is `UNKNOWN`; rollback cannot be reported as
successful and no generic path cleanup is allowed.

## 7. Response loss and drift

| Event | Required result |
|---|---|
| Raw E response lost before Main journal CAS | `UNKNOWN`/manual; retain residue; never replay E |
| Main journal CAS response lost | Discover/read only the exact expected old/new journal heads; conflicting truth is `UNKNOWN` |
| R or V response lost | Fresh same-command read-only reconciliation from the stored publication |
| F response lost | `reconcileFinalize` from the stored final authority |
| Rollback response lost | Fresh command-specific reconciliation from its stored publication |
| Same-byte new inode, same-inode rewrite, ancestor/root/recovery/History drift | `UNKNOWN`; preserve all evidence |
| Missing or partial formal record set | `UNKNOWN` unless the stored terminal explicitly proves completed cleanup |

The Developer Preview threat model prioritizes crashes, response loss, accidental concurrent
editing and path replacement. An active same-UID attacker who can manipulate already-open private
directory entries is an explicit **P2 residual**, not a reason to add another recovery authority or
block A1b indefinitely. Existing owner-only permissions, no-follow traversal, held descriptors,
atomic replacement and drift detection remain required; no claim of protection against every
same-UID adversarial interleaving is made.

## 8. One A1b exit gate

A1b has one review and one exit, not separate schema/wire micro-signoffs. Exit requires one
production mixed journey covering E -> Main journal CAS -> fresh R/V -> History -> F/ACK/cleanup,
plus the formal `ROLLBACK_CREATE` zero-net-write branch, response-loss/drift cases, focused gates,
production Main/native/filesystem evidence and independent review with P0=0 and P1=0.

Until that single exit is green, A1b remains NO-GO and A1c/A2/A->B/Stage C/D/E remain frozen.
