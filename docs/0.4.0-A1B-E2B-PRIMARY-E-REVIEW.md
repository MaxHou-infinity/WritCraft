## 2. 首红与修订事实

1. 生产 valid EXISTING fixture 最初返回 `UNKNOWN`，未被 canonical-only 绿灯覆盖。
2. 首次接入 production terminal 后，native stdout 出现重复 `P\tOK`；删除重复 preamble 后，parser 继续因 terminal digest authority 不一致而拒绝。
3. digest 不一致定位为 C apply-token formatter 多传一个 `selectedId` 参数；删除多余参数后真实 `E` 首次返回 `COMMITTED`。
4. 正向测试曾以 synthetic identity 比较真实 apply record 而首红；测试改为从 runtime after-leaf identity 动态重建 canonical apply receipt，未放宽生产校验。
5. 首轮独立复核为 P0=0、P1=2、P2=0：缺少 old-before cleanup 后到 response 前的真实 pause/drift 证据，且正向 `COMMITTED` 未比较 marker bytes/full identity。
6. 修订加入 `WRITCRAFT_TEST_PAUSE_EXISTING_AFTER_COMMIT_CLEANUP`，覆盖 public/control/apply/marker × same-inode/new-inode 八个真实漂移；response 前重新校验 public after、artifact/marker/History/root/recovery、formal control/apply 与 transient absence。正向证据同步比较 marker 和 History 的 bytes 与完整 object identity。
7. 修订后同一独立 reviewer 对冻结六文件内容复核为 P0=0、P1=0、P2=0。该结论只证明本节窄层，不是本记录的 final binding 自签。
