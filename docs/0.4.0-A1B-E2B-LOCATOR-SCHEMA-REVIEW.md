## 1. Signed claim and explicit non-claims

This checkpoint freezes only five deterministic, same-suffix locator positions
per EXISTING item. The positions are derived from the complete request digest
and `selectedId` and are therefore reconstructible by a fresh `R` without a
directory scan:

- deterministic control basename;
- deterministic apply-receipt basename;
- deterministic rollback-receipt basename;
- deterministic before-quarantine basename;
- deterministic after-stage basename.

The before-quarantine and after-stage names are positions, not publication
identities. A name alone cannot authorize adoption, cleanup, or reconciliation
of an inode. All five names must be absent before control publication; after
control is durable, control must remain exact and the other four names must
remain absent immediately before stage creation. The required swap order is: create and
fsync/reopen-bind the exact after-stage, recheck all authority, atomically
`RENAME_SWAP` the public before leaf with after-stage so after-stage holds the
old-before inode, fsync both directories, then no-clobber rename after-stage to
before-quarantine and fsync both directories. The before/stage names remain
live transient positions, not publication identities; a stage or
before-quarantine name without a formal token is preserved and returns
`UNKNOWN`, and fresh `R` never adopts or deletes it. After the apply receipt,
the implementation must perform identity-bound cleanup of the old-before
locator using the held fd and recovery-directory fsync. Only after both
before-quarantine and after-stage are absent may `COMMITTED` or `UNCOMMITTED`
be returned; neither terminal state claims a persistent before locator.

This does not sign public Markdown replacement, held-fd quarantine, staging,
self-rollback, apply receipts, E/R/V/F, `ROLLBACK_CREATE`, mixed transaction
wiring, A1b, Stage A, A1c, A2, candidate, or release authorization. The final
binding is pending. The only implementation boundary opened by this review is
the future C public-swap slice, which must supply the separate publication
identity and durability proof.

## 3. Preserved review findings and evidence

The first locator review batch preserved P1=1 and P2=2: the initial contract
and matrix wording did not state the control-before-swap ordering, transient
absence terminal condition, or the distinction between deterministic positions
and publication identities. The revision batch closed those findings with
P0=0, P1=0, P2=0. A post-binding wording review then found P1=1: the previous
text did not distinguish the pre-stage absence check from the swap boundary.
The first wording correction then introduced another P1 by treating the
unbound before locator as terminal authority. The current correction freezes
the physical `RENAME_SWAP` order while retaining both before/stage names as
live-only transients that must be absent at either terminal. These findings are
recorded here and await rereview; they are not self-signed.

Evidence is pure-schema only:

- snapshot existing-restore native schema `20/20`;
- all five names exact-shape, same-suffix and two-item globally unique;
- names frozen and derived from the complete request authority;
- `node --check` and `git diff --check` clean.

No runtime collision, fresh `R`, native public swap, or lifecycle test is
claimed by this record. Those belong to the next C public-swap checkpoint.

## 4. Dispatch boundary
