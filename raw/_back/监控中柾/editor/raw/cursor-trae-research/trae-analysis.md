## 1. 一句话定义 + 起源故事

**一句话定义：**

Trae（trae.ai / trae.com.cn）是字节跳动推出的 AI 原生集成开发环境（AI Native IDE），基于 VS Code 内核构建，分国际版和国内版双轨运营，定位为"AI 驱动的智能编程伙伴"，核心理念是"人机协同"而非简单 AI 插件叠加。

**起源故事：**

- 2025 年 1 月，字节跳动海外公司 SPRING PTE 发布 Trae 国际版（trae.ai），集成 Claude 3.5 / GPT-4o 等顶级模型，主打免费策略快速获客
- 2025 年 3 月 3 日，Trae 国内版（trae.com.cn）上线，集成 DeepSeek V3/R1 和豆包 1.5 Pro，被称为"中国首款 AI 原生 IDE"
- 2025 年 5 月 27 日，国际版 v1.4 重大更新，启动商业化，告别纯免费时代
- 2025 年 7 月 21 日，SOLO 模式上线，定位"Context Engineer"，业内首个基于上下文工程的 AI 自主开发模式
- 2026 年 2 月 24 日，国际版全面切换为 Token 计费会员体系（Lite $3～Ultra $100/月）
- 2026 年 6 月 29 日，国际版 v3.5.73 发布，整合内置智能体，开放企业版
- 2026 年 7 月 2 日，国内版 v3.3.25 发布，持续迭代

## 2. 核心 5 大功能

### 2.1 双重开发模式

- **IDE 模式**：保留完整 IDE 工作流（编辑器、终端、调试、插件、Git），适合精细控制代码改动和执行过程
- **SOLO 模式**：以 AI 为主导，自然语言或语音输入需求，AI 自动规划任务（代码生成→测试→预览→变更总结），适合复杂项目自动化开发

### 2.2 AI 编程能力矩阵

| 能力 | 说明 |
|------|------|
| **模型** | 内置多款先进模型，支持 API Key 接入自定义模型 |
| **智能体（Agent）** | 通过 @Agent #Context 协作，支持自定义 Agent（MCP Server / 工具集配置） |
| **CUE 代码补全** | 代码补全、链式补全、多行修改、修改点预测、智能导入/重命名（Python/TS/Go） |
| **上下文** | 支持文件、文件夹、代码片段、终端输出、Git 仓库、文档集、网页作为上下文 |
| **Builder** | 类似 Cursor Composer，可端到端生成项目结构和初始代码 |

### 2.3 AI 内联 / 代码补全

- 实时 AI 代码建议，多行修改自动补全
- 智能导入依赖、智能重命名引用
- 修改点预测与跳转

### 2.4 Builder 模式（项目生成）

- 通过自然语言描述需求，AI 自动拆解需求 → 生成代码框架 → 运行验证 → 结果预览
- 支持多模态输入（文字 + 图片），生成交互式原型
- 从 0 到 1 创建完整项目，省去从零开始的步骤

### 2.5 Chat 模式（多文件对话）

- 支持多文件上下文同时对话
- 可针对整个代码仓库提问、理解依赖关系
- AI 回答基于完整项目上下文，非简单代码片段

## 5. 隐私 / 安全

### 正面：隐私模式 + 沙箱

- **隐私模式**：开启后，对话内容、代码片段、AI 生成输出不用于数据分析、产品优化或模型训练；代码库文件始终保存在本地设备
- **沙箱运行**：Agent 生成的命令可在受限环境中执行，文件访问控制 + 高风险命令拦截，降低误操作风险

### 负面：2025年7月数据争议

**事件起因（2025年7月24日起）：**

- 开发者（网名 segmentationf4u1t）在 GitHub 爆料：Trae 在禁用遥测选项后，仍在7分钟内发起约500个网络连接、上传约26MB 数据
- 上传数据包括：系统信息（OS/CPU/内存/屏幕分辨率）、设备 ID、用户/机器/会话唯一标识符、文件类型/打开的文件/会话时长/专注状态、响应时间/错误状态/SDK版本、地区/语言/时区偏移量、项目工作区 ID、近期文件（已混淆）

**字节官方回应：**

- 所收集数据仅限"非敏感的产品性能指标和错误日志"（页面点击、功能使用频率等）
- 声称独立于 VSCode Telemetry 体系，关闭 VSCode 遥测不等于关闭 Trae 遥测
- 承诺30天内推出隐私控制面板升级
- 2026年6月最新版本（v3.5.73）已提供隐私模式功能

**额外发现：**

- Trae 存在可远程激活的"热更新"机制
- Discord 社区对"Track"关键词自动禁言7天（官方称系防广告机制误触发，已修复）

### 企业用户风险提示

- 字节跳动已于2025年5月28日发布内部邮件，要求6月30日起分批次禁用第三方 AI 编程工具（Cursor、Windsurf 等），改用自研 Trae
- 欧盟数据保护委员会（EDPB）已关注此事
- 国内工信部门启动同类产品合规性排查
- 部分企业已暂停 Trae 部署计划

## 8. 对 WritCraft 写作 IDE 的可移植性矩阵

> WritCraft（备注：项目内定位为 AI 写作 IDE，对标 AI 编程 IDE）可从 Trae 迁移/借鉴的能力如下：

| 能力维度 | Trae 实现方式 | 可移植到 WritCraft 的可行性 | 说明 |
|----------|-------------|--------------------------|------|
| **AI 模型集成** | 内置 + API Key 自定义 | ✅ 高 | 直接复用架构，换写作模型即可 |
| **上下文管理** | 文件/文件夹/仓库/网页作为上下文 | ✅ 高 | 写作场景可扩展至文档集、笔记库 |
| **智能体（Agent）** | @Agent #Context 协作，MCP 支持 | ✅ 高 | 写作 Agent 可定义写稿/改稿/审稿智能体 |
| **CUE 补全** | 实时代码补全、修改点预测 | ⚠️ 中 | 写作场景对应智能补全、语义续写，需定制 |
| **Builder 模式** | 自然语言生成项目代码 | ⚠️ 中 | 可参考为"自然语言生成文章框架/草稿" |
| **SOLO 模式** | Context Engineer 自主执行 | ⚠️ 中 | 写作场景可对应"自主撰写→修改→审校"流程 |
| **隐私模式** | 本地处理 + 不用于训练 | ✅ 高 | 写作场景同等重要，文档隐私敏感 |
| **沙箱执行** | 命令在受限环境运行 | ❌ 低 | 写作场景无命令执行需求，架构不适用 |
| **Git 版本控制** | 内置 Git 工作流 | ✅ 高 | 写作版本控制完全适用 |
| **插件生态** | VS Code 插件兼容 | ✅ 高 | 直接兼容，但需评估写作插件需求 |
| **多端同步** | TRAE Work（网页/桌面/移动） | ⚠️ 中 | WritCraft 移动端可能非核心优先级 |
| **飞书/字节生态** | 豆包模型、火山引擎 | ❌ 不适用 | 写作 IDE 应保持中立，不绑定单一生态 |

**总结**：Trae 的 AI 架构（模型层→智能体层→上下文层→工具层）对 WritCraft 有高度参考价值，尤其 Agent 协作模式和上下文管理机制可直接借鉴。
