## 一、V0 范围定义（一个月）

> **V0 的目标不是"完美产品"，而是"技术可行性验证 + 核心价值验证"**

## 二、V0 退出条件（量化三条路）

### 2.1 Continue（继续 V1）

**满足全部 3 条**：
- ✅ 10名内测作者中 ≥ 7人 每天使用 ≥ 30分钟（DAU 活跃）
- ✅ ⌘K 修改接受率 ≥ 60%（说明 AI 建议被用户信任）
- ✅ Plan Mode 完成率 ≥ 50%（说明大纲→写作路径被用户接受）

### 2.2 Pivot（技术路线调整）

**满足任一条件**：
- ⚠️ TipTap + MiniMax 集成遇技术瓶颈（AI diff 视觉难做）
  - **Pivot 方案**：换用 Lexical 重写 editor 核心；或换 OpenAI API 直连
- ⚠️ MiniMax API 速度不满足 ⌘K 实时性（< 500ms）
  - **Pivot 方案**：⌘K 降级为"异步确认模式"（1-3秒延迟可接受）；或换 o3-mini
- ⚠️ Plan Mode 接受率 < 30%（无大纲派强烈抵触）
  - **Pivot 方案**：Plan Mode 降级为"可选入口"而非默认路径；V0 主路径改为"直接写作+⌘K"

### 2.3 Abandon（项目暂停）

**满足任一条件**：
- ❌ 2周后仍无 5名 内测写作者（用户招募失败）
- ❌ 内测作者平均使用时长 < 10分钟/天（第2-4周统计）
- ❌ MiniMax API 异常 > 1天不可用（无备选方案）
- ❌ TipTap 技术难点 > 3天 未解决（无内部能力解决）

## 四、关键决策点

### 4.1 V0 第一支持文体的选择依据

**建议：方法论文籍**（而非长篇小说）

理由（COPE 原则）：
- Max 主人的专业经验最匹配：咨询/管理学方法论 → 直接可用 COPE 案例
- 方法论作者是有明确付费场景的专业用户（SaaS 订阅习惯好）
- Plan Mode（大纲先于写作）对方法论最天然适配（Ray Dalio 原则树框架）
- 长篇小说是次优先——叙事性更强，Plan Mode 可能抵触（Murakami 警告）

### 4.2 Plan Mode 具体形态

**5个 prompt 模板**（Week 1 必须交付）：

```
【开场模板】
输入：写作目标 + 目标读者
输出：开场钩子（3个选项）+ 理由

【主旨模板】
输入：章节标题
输出：本章核心主张（1-2句）+ 支撑逻辑（3点）

【大纲模板】
输入：主旨句
输出：Part→Chapter→Section→Paragraph 多级树；每节点填"本章主旨"1-2句

【立意模板】
输入：段落/章节草稿
输出：立意评估（强/中/弱）+ 具体强化建议（1条）

【收尾模板】
输入：章节/全文章节
输出：收尾呼应方式（3种）+ 最终金句建议
```

**重要约束**：Plan Mode 是"可选锚点"，不是强制入口。T8 N2 警示无大纲派（King/Murakami）可能强烈抵触，V0 必须允许用户跳过 Plan Mode 直接写作。

### 4.3 MiniMax 主力模型分工

| 任务 | 模型 | 理由 |
|------|------|------|
| ⌘K 实时修改 | M2.7-highspeed | <200ms 延迟，实时性必须 |
| 长文生成/改写 | M3 | 1M tokens，长篇上下文 |
| 图像章节插图 | image-01 | $0.0035/张，成本极低 |
| 文档资料参考 | MiniMax doc API | PDF/DOCX 解析（V1） |

**不用 MiniMax 的场景**（红线）：
- 强推理任务 → OpenAI o1/Claude Opus
- 极长上下文 >1M tokens → Gemini 1.5 Pro
- 创意极限发散 → Claude 3.5 Sonnet

### 4.4 4周 V0 硬卡：不是"完美产品"——而是"3人内测"

V0 的目标不是交付完整功能集，而是**用最小成本验证核心假设**：

```
Week 1 结束：技术路径 3 人确认可跑（Max + 2名帮手）
Week 2 结束：⌘K 功能 3 人真实使用（每周>5h）
Week 3 结束：引用功能 3 人真实生产内容（5000字+）
Week 4 结束：10 人内测（含5名 HRBP），数据驱动 Continue/Pivot/Abandon
```
