# 笔触 · WritCraft — 产品需求与价值说明

> 文档版本：v4.0 | 2026-07-28（0.0AA Main-owned Chat 多轮连续性）
> 发起方：Max Hou
> 状态：**V0 候选原型，未完成、未发布**
> 权威边界：产品规格看 `docs/WRITCRAFT-PRD-V3.md`；工程事实、测试证据与唯一 TODO 看 `v0/DEVELOPMENT-STATUS.md`。本文件只解释目标用户、产品价值与当前范围，不得据此重开历史任务。

## 一、产品定义

笔触 · WritCraft 是一款面向**方法论类专业长文作者**的 Cursor 式本地 AI 写作 IDE。它把项目、文件和段落三级写作作用域，`edit.md` 项目 Prompt、Inline Diff、Chat、Changes/History、Research、来源/脚注与一致性图谱放在同一工作区，让作者始终保有最终决定权。

产品不宣称“替作者写书”，也不使用“国内第一”等未经验证的市场表述。V0 的核心目标是减少写作工具切换、让 AI 修改可审查、让跨章节事实和变量可追溯。

## 二、目标用户与核心问题

V0 聚焦一类主用户：正在撰写方法论书籍、专业报告或结构化知识长文的个人作者。

待真实作者样本验证的问题假设：

- 内容跨越多章，主旨、目标读者、术语和统计口径容易漂移。
- 作者需要在编辑器、对话 AI、浏览器、资料库和图片工具之间频繁切换。
- AI 往往返回整篇结果，作者难以判断改了什么、为何修改以及是否可撤销。
- 人物、概念、变量、时间和来源之间的冲突难以人工持续追踪。

学术、法律和咨询文本可作为相邻验证场景，但不再把小说作者或泛内容创作者写成 V0 目标用户。

## 三、V0 产品主链

1. **项目启动**：新建或打开本地 Markdown 项目，以根目录 `edit.md` 定义主旨、目标、结构、语气、关键实体、变量和来源规则。
2. **三级工作区**：在项目树中切换文件；AI 请求明确选择 project、file 或 selection 作用域。
3. **段落级修改**：`⌘K` 生成原位红删绿增 Diff；预览零写盘，接受后经 Main 权威事务进入 History，可安全撤销。
4. **文件与项目协作**：Chat 支持 `@file`、`@folder`、`@chapter`、`@section`、`@entity`、`@source`；Chapter/Plan 只生成可审阅提案，不直接改稿。
5. **来源与研究**：来源保持只读；Research 结果以 Claim / Source / Boundary 进入专用 Changes，不把用户提供的来源等级当作事实背书。
6. **一致性图谱**：按人物、变量、关系、时间、文件和问题查看证据，定位冲突、遗漏和陈旧证据，再交接到 Changes。
7. **图片**：`image-01` 只允许显式触发、预览、评分和人工插入；Coding Plan Key 不能调用图片，完整 `sk-api-` 才能进入付费验收。

## 四、作者控制与安全边界

- Renderer 不拥有文件系统、网络、revision 或写入权限；Main 是唯一权威边界。
- AI 结果默认只读预览，所有正文修改必须经过 ChangeSet/History。
- 项目切换、文件 revision、选区、上下文 generation 或来源变化会使旧结果失效。
- Key、正文、Prompt、模型原文、项目名和路径不得进入诊断或验收记录。
- 不做一键生成整本书、自动接受改稿、作家风格模仿、多人实时协作、移动端或公开云同步。

## 六、已确认的本地产品缺口

按 2026-07-28 PRD→源码审计，0.0Z 已关闭 `edit.md` 章节化上下文与 Inspector 披露，0.0AA 已关闭 Main-owned Chat 最近对话、多轮连续性、可见重置和同项目重开隔离；仍有一项不能写成“已完成”：

1. **普通 Markdown 回收区 UI**：Main service 已有回收清单和恢复能力，但 App 尚无可见列表与单项恢复入口。

下一本地任务只做这一项并独立签字。不得用已关闭的 Chat、Prompt、watcher、安全或历史测试任务替代这个产品缺口。

## 七、V0 完成门禁

本地产品缺口关闭后，仍需：

- 作者显式选择满足合同要求的真实项目，并在隔离工作副本中完成五段旅程。
- 使用完整 `sk-api-` 完成一次真实付费图片质量、耗时和费用验收。
- 收集真实作者的接受率、撤销率、任务完成率、连续写作时长和定性反馈。
- 基于最终源码重建 App/ZIP，完成干净账户、Developer ID、notarization 与 Gatekeeper 验收。

只有这些门禁全部满足，才能讨论 V0 完成、公开分发或 V1 Go/No-Go。

## 八、价值验证指标

| 指标 | 目的 |
|---|---|
| Inline/Changes 接受率与撤销率 | 判断 AI 建议是否有用且可控 |
| 项目任务完成率 | 判断三级工作区是否减少跨工具切换 |
| 引用/来源定位成功率 | 判断溯源是否真正节省核对时间 |
| 一致性 Issue 采纳率 | 判断图谱是否帮助发现真实冲突 |
| 连续写作时长与主观打断点 | 判断产品是否保护写作心流 |
| 付费意愿与图片采纳率 | 判断商业价值和多模态价值 |

商业指标必须来自真实作者样本；fixture、stub、自动化绿灯或单次 API 成功不能替代。
